# 11 系统级瓶颈与软硬件判定

## 本章目标

判断瓶颈是应用计算、调度、内存、磁盘、温度降频还是外部设备。

## 一组同时采集的命令

```bash
uptime
vmstat 1
mpstat -P ALL 1
pidstat -p PID -t -r -d -w 1
iostat -xz 1
cat /proc/pressure/cpu
cat /proc/pressure/memory
cat /proc/pressure/io
```

重点解释：

- `vmstat r`：等待 CPU 的可运行任务数。
- `us/sy/wa`：用户、内核和 I/O 等待比例。
- `cs`：上下文切换。
- `iostat await`：I/O 平均响应时间。
- PSI：任务因为资源不足被迫等待的时间比例。

## 学员任务

为三种模式分别记录：CPU 利用率、运行队列、RSS、major fault、I/O 吞吐、`await` 和 PSI。不能只根据程序模式名称作答。

## 判断框架

| 证据 | 主要怀疑方向 |
|---|---|
| 一个业务线程满核 | 算法、循环、复制、绘图 |
| run queue 很高 | CPU 容量或线程过多 |
| CPU 不高、I/O PSI 高 | 磁盘或同步写日志 |
| RSS 高且 memory PSI 高 | 队列、缓存、泄漏、设备内存不足 |
| 频率下降且温度高 | 散热和硬件降频 |
| 应用队列低但设备计数停止 | 驱动、FPGA 或链路 |

## ARM64 现场检查

```bash
lscpu
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
grep . /sys/class/thermal/thermal_zone*/temp
cat /proc/interrupts
dmesg -T | tail -200
```

路径取决于具体板卡。QEMU 和 WSL 无法还原真实温度、PMU、IRQ 和 DMA 行为，最终结论必须来自目标设备。
