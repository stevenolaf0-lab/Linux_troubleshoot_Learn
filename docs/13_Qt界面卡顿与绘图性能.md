# 13 Qt 界面卡顿与绘图性能

## 本章目标

区分 GUI 事件循环阻塞、刷新风暴、历史数据增长和后台计算瓶颈。

## 构建

```bash
sudo apt install qtbase5-dev    # Qt 5
# 或安装发行版提供的 qt6-base-dev
cmake --preset x86-release
cmake --build --preset x86-release --target qt_scope_freeze
BIN=./build/x86-release/demos/13_qt_scope_freeze/qt_scope_freeze
```

## 实验

```bash
$BIN --mode fixed
$BIN --mode freeze
$BIN --mode repaint
$BIN --mode history
```

窗口标题显示 GUI 心跳间隔和历史点数。定时器目标周期为 50 ms。

## 学员任务

1. 哪种模式心跳会稳定超过 300 ms？
2. 哪种模式强制同步重绘？
3. 哪种模式点数和 RSS 持续增长？
4. 使用 `top -H` 与 `perf record -g -p PID` 找到 GUI 线程热点。

## 实战答案

- `freeze` 在 GUI 线程执行 300 ms 耗时任务，事件循环无法处理输入和绘制。
- `repaint` 强制同步绘制；高频数据到来时容易形成刷新风暴。
- `history` 不限制点数，长期运行会增加内存和每帧遍历成本。
- `fixed` 使用 `update()` 合并绘制请求，并只保留最近 2048 点。

## 生产设计

- 接收、解析、FFT 放到工作线程。
- GUI 以固定帧率拉取最新结果，不为每个数据包绘图。
- 限制历史长度，显示点数不超过像素分辨率所需数量。
- 用 `QElapsedTimer` 记录接收、解析、算法、排队、展示时间。
- 用周期 `QTimer` 检测事件循环延迟。
- 不在持锁状态下发跨线程 GUI 信号。

对 QCustomPlot 应优先使用排队刷新、数据抽取和固定刷新率，谨慎使用立即重绘。
