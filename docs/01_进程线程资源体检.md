# 01 进程、线程与资源快速体检

## 本章目标

在一分钟内判断问题属于高 CPU、线程增长、休眠等待还是进程整体异常。

## 核心命令

```bash
top -p PID
top -H -p PID
ps -L -p PID -o pid,tid,comm,stat,pcpu,psr,wchan:24
pidstat -p PID -t 1
cat /proc/PID/status
ls /proc/PID/task | wc -l
```

常见线程状态：

- `R`：正在运行或等待 CPU。
- `S`：可中断睡眠，常见于定时器和条件变量。
- `D`：不可中断睡眠，常见于内核 I/O 等待。
- `Z`：僵尸线程或进程。
- `wchan`：线程在内核中的等待位置。

## Demo

```bash
cmake --build --preset x86-debug --target resource_watch

./build/x86-debug/demos/01_resource_watch/resource_watch \
  --mode cpu --duration 60 &
PID=$!
top -H -p "$PID"
pidstat -p "$PID" -t 1
```

线程增长场景：

```bash
./build/x86-debug/demos/01_resource_watch/resource_watch \
  --mode thread-leak --duration 60 &
PID=$!
watch -n 1 "ps -L -p $PID -o tid,comm,stat,wchan:20"
```

## 学员任务

分别找出：

1. `cpu` 模式中占用核心的线程名和 TID。
2. `thread-leak` 模式中线程数量的增长速率。
3. 新线程当前等待在哪个内核函数。

## 实战答案

`cpu` 模式的 `fft-hot-loop` 长期占用一个逻辑核心。`thread-leak` 每秒创建一个 `leaked-worker`，线程会停在 futex/条件变量等待路径。问题不是单个线程 CPU 高，而是生命周期管理缺失。

生产环境中要同时记录进程 CPU 和各线程 CPU。只看进程总占用无法判断是接收、算法、数据库还是 GUI 线程。

## 修复原则

- 固定工作线程数量，使用线程池。
- 对创建和退出做计数。
- 为所有长期线程设置名称。
- 停止流程必须唤醒并 `join` 工作线程。
- 监控线程数是否随运行时间单调增长。
