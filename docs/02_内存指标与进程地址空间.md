# 02 内存指标与进程地址空间

## 本章目标

区分真实泄漏、无界队列、有上限缓存和短期内存峰值。

## 核心指标

- `VmSize`：虚拟地址空间，不等于实际占用。
- `VmRSS`：当前驻留物理内存。
- `RssAnon`：匿名内存，堆和栈通常在这里。
- `RssFile`：文件映射和动态库页。
- `PSS`：共享页按比例分摊，更适合多进程比较。

## 核心命令

```bash
pidstat -r -p PID 1
watch -n 1 'grep -E "VmRSS|RssAnon|VmSize|Threads" /proc/PID/status'
pmap -x PID | tail -1
cat /proc/PID/smaps_rollup
```

## Demo

```bash
cmake --build --preset x86-debug --target memory_growth
./build/x86-debug/demos/02_memory_growth/memory_growth \
  --mode queue --duration 60 &
PID=$!
pidstat -r -p "$PID" 1
```

依次测试：

```bash
--mode leak
--mode queue
--mode cache
--mode fixed
```

## 学员任务

只根据 RSS 曲线和 Demo 日志，判断四种模式的差异。特别回答：RSS 增长是否一定等于泄漏？

## 实战答案

- `leak`：每秒丢失 1 MiB 所有权，退出时工具可报告泄漏。
- `queue`：对象仍可达，但生产大于消费，队列和 RSS 同时增长。
- `cache`：前 16 秒增长，达到上限后稳定，是有界缓存。
- `fixed`：临时内存反复分配释放，RSS 不一定立刻下降，这是分配器复用，不足以证明泄漏。

因此，必须把 RSS 与队列长度、缓存数量和泄漏工具报告放到同一时间轴。

## 进一步验证

```bash
valgrind --leak-check=full \
  ./build/x86-debug/demos/02_memory_growth/memory_growth \
  --mode leak --duration 5
```

## ARM64 提醒

ARM 目标机内存通常更小，更容易由队列积压触发 OOM。额外检查 `dmesg -T | grep -i -E 'oom|killed process'` 和 cgroup 内存限制。
