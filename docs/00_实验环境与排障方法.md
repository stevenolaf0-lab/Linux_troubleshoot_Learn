# 00 实验环境与统一排障方法

## 本章目标

在使用任何工具前建立可复现环境，并让日志能够回答：何时、哪个线程、处理到哪一帧、队列多长、耗时多少。

## 准备环境

```bash
uname -a
uname -m
cat /etc/os-release
gcc --version
cmake --version
ulimit -a
```

保存版本信息：

```bash
mkdir -p evidence
{
  date --iso-8601=seconds
  uname -a
  cat /etc/os-release
  gcc --version | head -1
} | tee evidence/environment.txt
```

## 编译和运行

```bash
cmake --preset x86-debug
cmake --build --preset x86-debug --target baseline_pipeline
./build/x86-debug/demos/00_baseline_pipeline/baseline_pipeline \
  --mode normal --duration 10
```

观察线程名：

```bash
pidof baseline_pipeline
ps -L -p PID -o pid,tid,comm,stat,pcpu
```

## 学员任务

运行 `--mode faulty`，回答：

1. 仅凭 `running` 能否判断程序处理了多少帧？
2. 能否知道队列是否积压？
3. `ps -L` 中能否区分生产者和消费者？
4. 出现延迟时能否关联到具体时间？

## 实战答案

故障模式没有线程名、统一时间戳、序号、吞吐和队列指标。程序“还活着”不等于程序工作正常。正常模式会输出：

```text
2026-... tid=... produced=... consumed=... queue=... latency_us=...
```

这组字段是后续所有实验的最小观测基线。

## 排障记录模板

```text
现象：
开始时间：
首次异常时间：
输入数据与参数：
软件版本/构建类型：
PID 与关键 TID：
CPU/RSS/线程数：
生产速率/消费速率/队列长度：
端到端延迟：
已排除假设：
当前根因证据：
```

## ARM64 提醒

方法完全相同。ARM64 额外记录 `uname -m`、页大小 `getconf PAGESIZE`、CPU 型号和动态库架构。QEMU 数据只能验证功能，不能作为性能结论。
